# 📋 실시간 그룹 메뉴 추천 서비스 ("아무거나버스터 / AmugeonaBuster") 요구사항 정의서

본 문서는 실시간 그룹 스와이프 투표, 맛집 추천 및 웰스토리 스마트 식단 자동 배달 서비스인 **"아무거나버스터(AmugeonaBuster)"**의 기능 및 비기능적 요구사항을 정의합니다. 본 사양서는 프로젝트 전체 구현 단계에서 비즈니스 정합성을 검증하는 기준으로 삼습니다.

---

## 1. 서비스 개요 및 목적
*   **목적:** 친구나 직장 동료 등 다수가 모였을 때, "오늘 뭐 먹을지" 고민하는 시간을 단축해 주는 모바일 친화형 실시간 의사결정 도구이자, 매일 점심/저녁 구내식당 식단을 자동으로 카톡으로 받아볼 수 있는 편의 서비스입니다.
*   **핵심 가치:** 
    *   **접근성:** 별도의 회원가입 없이 링크 하나로 10초 만에 대기실에 참가합니다.
    *   **재미:** 소개팅 앱처럼 맛집 카드를 스와이프하여 빠르고 직관적으로 투표를 마치고, 소금 커피 3D 복불복 내기 미니게임으로 커피 골든벨을 가립니다.
    *   **실용성:** 투표 결과를 기반으로 실제 주위 맛집 목록과 연계 지도 뷰를 노출하고, 삼성전자 웰스토리 식단을 알림 설정한 시간에 맞춰 카톡방으로 자동 전송합니다.

---

## 2. 주요 액터 (Actors)
1.  **방장 (Host):** 방을 최초 생성하고, 모임의 약속 장소(위치)를 설정하며, 투표 게임을 강제 시작시킬 수 있는 권한을 가진 유저입니다.
2.  **참가자 (Guest):** 초대 링크 또는 입장 코드를 통해 방에 참가하여 실시간 투표에 기여하거나 커피 미니게임에 참가하는 유저입니다.
3.  **웰스토리 구독자 (Subscriber):** 구내식당 알림 서비스를 신청하여 카카오톡으로 당일 식단 정보를 정기 수령하는 유저입니다.

---

## 3. 기능적 요구사항 (Functional Requirements)

### F-100: 방 생성 및 관리 (Room Management)
*   **F-101 (방 생성):** 방장은 약속의 기준 주소(예: "강남역", "판교역" 등)를 지정하여 방을 생성합니다.
*   **F-102 (초대 생성):** 방 생성 시 1회성 난수 형태의 방 고유 코드(`ROOM-XXXX`) 및 간편 참여 URL이 자동 생성되어 클립보드에 복사할 수 있는 기능을 제공합니다.
*   **F-103 (방 소멸):** 방이 생성된 지 3시간 동안 최종 매칭이 이루어지지 않거나 비활성화 상태인 경우, 백엔드 스케줄러를 통해 메모리와 영속 계층에서 자동으로 제거되어야 합니다.

### F-200: 실시간 대기실 및 참가 (Lobby Phase)
*   **F-201 (무가입 입장):** 참가자는 링크를 클릭한 뒤 닉네임만 입력하고 바로 대기실로 참가합니다. (식별은 세션/쿠키 기반 고유 ID 활용)
*   **F-202 (실시간 참가자 브로드캐스트):** 새로운 유저가 참여하거나 이탈할 때마다 대기실에 있는 모든 참가자의 화면에 참여 유저 목록이 실시간(WebSocket)으로 갱신되어야 합니다.
*   **F-203 (준비 완료 상태 제어):** 모든 참여자는 대기실에서 대기하며, 방장은 전원이 접속한 것을 확인한 뒤 게임을 '시작'할 권한을 갖습니다.

### F-300: 실시간 메뉴 스와이프 게임 (Swipe Phase)
*   **F-301 (공통 메뉴 카드 분배):** 백엔드 서버는 한식, 일식, 중식, 양식, 분식, 아시안 등 대표 카테고리의 베스트 메뉴 15가지 카드를 모든 참여자에게 균등하게 제공합니다.
*   **F-302 (스와이프 동작):** 유저는 개별 메뉴 카드에 대해 다음 두 가지 중 하나를 무조건 선택해야 합니다.
    *   **Right Swipe (좋아요 👍):** 먹을 의향이 충분히 있음.
    *   **Left Swipe (싫어요 👎):** 절대 먹고 싶지 않음.
*   **F-303 (투표 현황 실시간 공유):** 누군가 스와이프를 마칠 때마다 "X명 중 Y명 완료" 상태가 실시간 소켓으로 동기화되어 실시간 참여감을 부여합니다.

### F-400: 합의점(Consensus) 도출 알고리즘
*   **F-401 (점수 합산 규칙):**
    *   `Like (👍)` = **+1점**
    *   `Dislike (👎)` = **-2점** (비선호 방지 페널티 가중치)
*   **F-402 (거부권 룰):** 특정 메뉴에 대해 참가자 중 한 명이라도 `Dislike`를 표시한 경우, 해당 메뉴는 최종 순위에서 즉시 제외됩니다. 단, 모든 메뉴가 제외되어 남는 메뉴가 없는 경우 **F-403** 예외 알고리즘으로 대체됩니다.
*   **F-403 (비토 폭탄 구제 알고리즘):** 모든 메뉴가 거부권을 당했을 경우, 거부권 룰을 일시 해제하고 순수하게 `(Like 개수 * 1) - (Dislike 개수 * 0.5)` 가 가장 높은 순으로 1, 2, 3위를 도출합니다.

### F-500: 위치 기반 주변 맛집 추천 (Map Phase)
*   **F-501 (외부 API 연동):** 최종 1위 메뉴가 결정되면, 방 설정 시 입력된 장소 좌표를 기반으로 카카오 로컬 API를 호출하여 반경 1km 이내의 해당 메뉴 검색 결과를 5개 확보합니다.
*   **F-502 (지도 리스트 바인딩):** 카카오맵 API 위젯을 프론트엔드에 렌더링하고, 조회된 5개의 맛집 위치를 마커(Marker)로 매핑하여 가게 이름, 평점, 전화번호를 매칭 결과를 얻은 모든 유저 화면에 실시간 노출합니다.

### F-600: 스마트 웰스토리 식단 카카오톡 알림 및 뷰어 (Welstory Alert & Viewer) [NEW]
*   **F-601 (카카오 로그인 연동):** 사용자는 카카오 OAuth 로그인을 통해 간편하게 본인 닉네임과 알림 설정 권한(`talk_message`)을 부여받아 알림 구독을 신청할 수 있습니다.
*   **F-602 (구내식당 지점 프리셋 제공):** 주요 삼성 계열 지점(삼성 DSR 타워, 수원 디지털시티 R5, 기흥 MR1, 화성 D1 등)의 프리셋 코드를 제공하며, 설정 시 동적으로 웰스토리 식단 스크래핑을 연계합니다.
*   **F-603 (알림 시간대별 식단 자동 매칭 발송):** 사용자가 설정해 둔 알림 시간대(`HH:mm`)에 맞춰 스케줄러가 당일 식단을 자동 매칭 및 필터링하여 카톡으로 발송합니다.
    *   `00:00 ~ 08:59`: **아침 식단**만 필터링하여 발송
    *   `09:00 ~ 12:59`: **점심 식단**만 필터링하여 발송
    *   `13:00 ~ 23:59`: **저녁 식단**만 필터링하여 발송
    *   *예외 Fallback*: 해당 시간대에 수집된 식단이 없는 경우 전체 식단을 발송하여 무장애 안정성을 기합니다.
*   **F-604 (모바일 대응 프리미엄 식단표 상세 모달):** 
    *   글래스모피즘 기반의 아침☀️ / 점심🌤️ / 저녁🌙 / 전체보기📅 4단 스위칭 탭 바를 제공하여 깔끔하게 식단 분류 조회가 가능합니다.
    *   사용자가 지정한 구내식당 지점 정보를 기반으로 실시간 동적 식단 조회를 수행합니다.
*   **F-605 (모바일 인앱 브라우저 스크롤 누수 완전 봉쇄):** 
    *   카톡 인앱 브라우저 및 iOS Safari 등 터치 드래그에 민감한 특수 웹뷰에서 모달 스크롤 시 뒷배경이 요동치거나 흔들리는 결함을 **Scroll Position Memory Lock(position: fixed 강제 변조 및 복원)** 및 **overscroll-contain** 기법으로 완벽히 차단합니다.

### F-700: 3D 복불복 커피 내기 게임 (3D Salt Coffee Game) [NEW]
*   **F-701 (프리미엄 3D 그래픽 에셋):** Meal, Bell, Coffee 등 고품격 3D 입체 일러스트 디자인을 메인 카드 및 버튼들에 정합하여 극도의 Premium UX 비주얼을 제공합니다.
*   **F-702 (소금 커피 3D 컵 셔플 게임):** 참여자들 중 단 한 명의 당첨자(소금 커피 💀 당첨)를 뽑는 카드 뒤집기 셔플 게임을 제공합니다.
*   **F-703 (당첨 정보 원천 은폐 - 하이브리드 3D 쉘):** 카드가 3D로 회전(Flipped)하기 전에는 브라우저 내부 소스코드 분석 등으로 당첨 컵(💀)을 찾아낼 수 없도록 앞면/뒷면 컨테이너 렌더링 조건을 엄격히 분리하여 무결하게 보안을 처리합니다.

## 4. 비기능적 요구사항 (Non-Functional Requirements)

### NF-100: 실시간성 및 응답 속도
*   **NF-101 (소켓 지연 속도):** 실시간 스와이프 진행 상황 및 로비 입장/퇴장 동기화의 메시지 브로드캐스트 지연 시간은 **500ms 이내**여야 합니다.
*   **NF-102 (API 시간 제한):** 카카오맵 API 호출 등 타사 API 연동 오류로 인해 시스템이 중단되지 않도록 **최대 2초**의 타임아웃을 적용하고, 실패 시 디폴트 더미 데이터 또는 에러 안내 카드를 표출합니다.

### NF-200: 확장성 및 동시성 제어
*   **NF-201 (동시성 제어):** 동일한 유저가 비정상적으로 스와이프 신호를 연속 두 번 발송할 경우(더블 탭 등), 백엔드에서는 최초 유효 요청 한 건만 인정하도록 멱등성을 보장해야 합니다.
*   **NF-202 (추상화 설계):** 임시 방 세션 관리는 JVM Local memory (`ConcurrentHashMap`) 기반으로 동작하도록 구성하지만, 스케일아웃을 대비하여 Redis Adapter로 즉시 갈아끼울 수 있도록 Port-Adapter 인터페이스 의존성 주입 구조를 갖춥니다.
*   **NF-203 (알림 배치 효율성):** 매 분 단위로 구동되는 정기 발송 스케줄러 배치는 `scheduledTime` 및 `isEnabled` 복합 인덱스를 적용한 DB 조회를 수행하여 탐색 속도를 최적화합니다.

## 5. 예외 및 예비 시나리오 (Edge Cases & Fallbacks)

| 예외 시나리오 | 동작 정의 (Fallback) |
| :--- | :--- |
| **게임 도중 참가자 네트워크 연결 끊김** | 60초간 대기 후 돌아오지 않으면 해당 유저의 세션을 강제 제거하고, 기존에 스와이프한 결과만 투표 합산에 유효 반영함. |
| **카카오 API 일일 트래픽 초과 or 장애** | 맛집 정보를 연동하는 대신 "지도가 아프대요! 직접 네이버/카카오 지도에서 [메뉴이름]을 검색해 보세요!"라는 친화적인 뷰로 대체 렌더링함. |
| **방장이 게임 진행 중에 나가버림** | 대기실 방장이 끊기면 접속해 있는 나머지 인원 중 가장 먼저 방에 입장했던 인원(또는 무작위 1인)에게 방장 권한을 자동 위임함. |
| **카카오 알림 전송 실패 (OAuth 만료)** | 401 Unauthorized 에러 발생 시 데이터베이스에 저장된 `kakao_refresh_token`을 사용하여 엑세스 토큰을 **자동 갱신(Token Refresh)** 한 뒤 즉시 재발송을 시도함. 만약 리프레시 토큰까지 완전히 만료된 상태라면 알림 상태를 `isEnabled = false`로 안전하게 끄고 비활성화합니다. |
